# Т-Банк — нативная версия 2.3.0

Неофициальный макет с вымышленными данными, не связанный с банком. Настоящие деньги, банк, NFC-эквайринг, реальные покупки/вакансии/подписки не подключены. Начальное предупреждение показывается **один раз на установку**, не при каждом запуске. Обычные меню не имеют постоянных DEMO-плашек. PDF обязательно помечены **«Образец, недействительно»**.

## APK и новый пакет

- **TBank-2.3.apk** — Android **8.0+**, версия **2.3.0**, versionCode **6**.
- Пакет по запросу: **`com.mvt.tbank`**, соответствует предоставленному Firebase Android-конфигу.
- Оформление выпущенной 1.1, восстановленное в 2.1, остаётся базой; интерфейс — Android Views/Canvas/VectorDrawable. **Не WebView**, HTML/JS/CSS-оболочки нет.
- Подпись тем же ключом. Но другой package name означает **отдельную установку**, а не обновление 2.2 `ai.arena.bankdemo`.

**Не удаляйте прежнюю 2.2, пока не перенесли нужные данные.** Для неё подготовлен необязательный `TBank-2.2-export.apk`: он обновляет только старый пакет, сохраняет данные и добавляет экспорт JSON. После экспорта откройте новую 2.3 → «Витрина → Все сервисы → Сохранение данных → Импортировать копию». Подробности: `qa/ПЕРЕНОС.md`.

## Firebase — важный внешний шаг

Настоящий запрос по вашему конфигу вернул **`CONFIGURATION_NOT_FOUND`** при анонимном входе. Тестовая учётная запись не была создана, данные не отправлялись. Нельзя утверждать, что реальная RTDB-синхронизация уже прошла сквозную проверку.

Владелец проекта должен:
1. **Firebase Console → Authentication → Начать → Способы входа → Анонимный → Включить**.
2. **Realtime Database → Rules**: опубликовать `firebase/database.rules.json`.
3. В APK открыть **«Витрина → Все сервисы → Сохранение данных»** и нажать **«Сохранить сейчас»**.

Клиент/очередь сохранения уже встроены. При недоступном проекте данные продолжают храниться локально. Статус «Все изменения сохранены» появляется только после успешной записи. Открытые всем правила блокируют загрузку профиля. Не используйте `.read: true`/`.write: true`. Подробное руководство и границы: **`firebase/SETUP.md`**.

Используются официальные Firebase Auth/RTDB HTTPS REST API, нормальная проверка TLS, авторизация отдельным Firebase UID, проверка приватности пути, ETag/If-Match и версии снимков. Клиентский API key и параметры Firebase обычным образом включены в приложение; административного/service-account ключа нет.

## Постоянный номер и вход

- Случайный **12-значный номер профиля** создаётся один раз, хранится отдельно от финансового состояния и не меняется от запуска, обновления, темы или сброса демонстрационных счетов. В профиле его можно скопировать.
- Это ID профиля, **не телефон**, не настоящий банковский номер и не способ угадать/открыть чужую облачную запись.
- При полной очистке данных/переустановке Android удаляет локальную идентичность. Для переноса используйте экспорт/импорт; облачный профиль по умолчанию анонимный и привязан к установке.
- **«Настройки → Вход в приложение»**: создать, изменить или отключить реальный локальный код-пароль. Изменение/отключение требует текущего кода. Есть ограничение попыток и блокировка после 30 секунд в фоне.
- Код хранится как PBKDF2-HMAC-SHA256 со случайной солью. Код/его верификатор не включаются в экспорт или RTDB. Firebase refresh token защищён Android Keystore / AES-GCM без открытого запасного хранения.
- Старый экран «подойдёт любой код» и обход «войти без кода» при включённом PIN удалены. Если PIN вообще не задан, вход не имитирует его проверку.

## Исправления по скриншотам

- Суммы операций не переносятся по пробелам и не превращаются в обрезанное «−10»; колонка измеряется по содержимому, сумма однострочная, значок ожидания сохранён.
- Даты истории и деталей читаемые, без вывода ISO-строки/служебного часового смещения.
- Собственные переводы, обмены и покупки инструментов не раздувают потребительские расходы. История проводок не удаляется.
- Вклады/накопительные счета имеют отдельный интерфейс: без оплаты картой, кэшбэка и «заблокировать карту». Их остаток пополняется переводом с собственного счёта.
- Калькулятор вклада, открытие и финансирование — одна местная атомарная операция. Непополняемый вклад не принимает повторное пополнение.
- Валюты обозначаются правильно; обмен — по фиксированным вымышленным курсам с явным округлением. Целые минимальные единицы и парные проводки.
- Адаптивная и монохромная иконка Android плюс варианты по плотностям; новые нажатия кнопок с масштабом и возвратом, с учётом системного отключения анимаций.
- Исправлена подсказка выбора кэшбэка; основная интерфейсная копия реагирует на English, а пользовательские имена/названия остаются данными.
- Изображения подушек заменены чёткими небрандовыми иллюстрациями, галерея не обрезает товар растягиванием миниатюры.

## Меню по третьему видео

Изучена новая запись около **15 минут 31 секунды**. Сетевые простои и внешняя страница с ошибкой TLS не копировались.

- Компактные «Платежи», способы перевода, поиск банка/поставщика, отдельные способы международного перевода.
- Вклады, выбор срока и условий; валютные счета и обмен; выпуск карты: владелец → дизайн → лимиты → результат.
- Подписка Pro, каталог партнёрских подписок и выбор тарифа — местная оплата и сохранённое состояние.
- Вакансии, фильтр графика, детали, отклик/отмена, список откликов и резюме — без отправки работодателям.
- Подарки, выбор вида/получателя, местная покупка и явно неплатёжный код подарка.
- Иллюстративный график инструмента с выбором периода и перемещением пальца; покупка/продажа остаются локальным учётом по фиксированным ценам.
- Прежние главная, карты, настройки, история, CSV, аналитика, кэшбэк/категории, предложения, T-Pay, лояльность с CODE128, QR/галерея, профиль, документы, дополнительные карты, заявки и игра сохранены.

**«Перевести» → выполнение → результат**, без отдельного экрана подтверждения; повторное нажатие во время выполнения не создаёт вторую операцию.

## Что сохраняется

Профиль, счета, остатки, история, настройки, избранное, карты лояльности/дополнительные карты, заявки, резюме, подарки, подписки, портфель и выбранный аватар. Снимок `stateJson` сохраняет пустые массивы/объекты и null без потерь RTDB. Секреты доступа и временные флаги входа в него не попадают. Формы до нажатия «сохранить/отправить» не считаются подтверждёнными данными.

Реальных банковских API, биржевых котировок, доставки, выполнения заявок оператором и автоматических реальных платежей нет. Напоминания/регулярные платежи — местные шаблоны, а не фоновый банковский планировщик. Схемы карт/адреса — условные, не GPS. T-Pay и защитные параметры не подключают настоящий терминал/банковскую биометрию.

## Приватность и разрешения

- Частный оригинал третьего видео, его кадры/листы анализа, браузерное хранилище и 11 присланных скриншотов удалены локально после анализа. Ранее удалённые первые две записи повторно не загружались.
- В ресурсах — только небольшие неперсональные коммерческие иллюстрации/узоры и новый товарный декор. Имена, телефоны, суммы, номера карт/лояльности из записи не переносились. EXIF/XMP отсутствуют.
- Начальный профиль/контакты вымышлены, телефоны `(000)`. Разрешения: **CAMERA, VIBRATE, INTERNET, ACCESS_NETWORK_STATE**; камера необязательна. Контакты, SMS, геопозиция и банковские аккаунты не читаются.
- Интернет нужен только для выбранного Firebase-проекта и его Auth API. Автосохранение включается после одноразового информирования/согласия; можно продолжить без синхронизации.
- Кадры камеры не записываются/не отправляются. Фото, которое сам пользователь выбрал в профиль, включается в его облачную копию при включённой синхронизации.
- Android backup отключён. Закрытого ключа подписи в исходном архиве нет. Системные «Поделиться» и сохранение файла запускаются явным действием.
- Локальная очистка не удаляет исходник у владельца ссылки/вложение на сервере чата.

## Сборка

Linux, Python 3, JDK 11+, Android SDK Platform 35, Build Tools 35.0.0. Gradle/Node/npm не нужны. Библиотеки и шрифты уже включены; сама сборка работает без сети.

```bash
export JAVA_HOME=/path/to/jdk-11
export ANDROID_SDK_ROOT=/path/to/android-sdk
export BANK_SIGNING_KEY=/path/to/your-signing.p12
python3 build_apk.py ../TBank-2.3.apk
```

По умолчанию alias `demo`, пароль `android`; для другого alias/пароля измените команду подписи в `build_apk.py`. Прежний закрытый ключ не распространяется. Для независимой локальной сборки:

```bash
mkdir -p android/.signing
keytool -genkeypair -alias demo -keyalg RSA -keysize 2048 \
  -storetype PKCS12 -keystore android/.signing/demo-signing.p12 \
  -storepass android -keypass android -validity 10000 \
  -dname "CN=Local Native Build"
python3 build_apk.py ../TBank-Native-local.apk
```

С другим ключом нельзя обновить прежний APK: потребуется удалить прежнюю установку, потеряв её локальные данные. Это пример для макета, не ключ настоящего финансового приложения.

```bash
python3 tests/run_jvm_tests.py
python3 qa/check_apk.py ../TBank-2.3.apk
```

Статическому аудитору нужен Pillow. Аудитор также сравнивает сертификат с исходной подписью: независимо подписанная сборка ожидаемо не пройдёт именно эту проверку. `lib/json-20240303.jar` нужен только JVM-тестам, не входит в APK.

### Дополнительные нативные UI-тесты

После успешной сборки APK нужны Maven 3.8+ и доступ к Maven Central/Google Maven. **При пустом кэше тестовые зависимости занимают несколько сотен МБ**; они не включены в исходники или APK и хранятся в `.cache`.

```bash
export ANDROID_SDK_ROOT=/path/to/android-sdk
# MAVEN можно не задавать, если mvn находится в PATH.
export MAVEN=/path/to/maven/bin/mvn
python3 qa/run_native_ui.py
```

Скрипт упаковывает свежие скомпилированные классы, проверяет контрольные суммы Android framework/AndroidX, обновляет список маршрутов и запускает suite. Путь к проекту передаётся через окружение и Maven filtering, а не зашит в свойствах. `NATIVE_TEST_CACHE` позволяет выбрать внешний каталог кэша. Тестовая среда ограничена API 28; SDK 35 используется для компиляции.
