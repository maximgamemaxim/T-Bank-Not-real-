# Firebase для com.mvt.tbank

Клиент уже читает параметры вашего Android-приложения из `google-services.json`. Пакет APK — **com.mvt.tbank**. Используются Firebase Authentication и Realtime Database через официальные HTTPS REST API; Google Play Services и WebView не нужны.

## Важный результат проверки

Реальный запрос анонимного входа по предоставленному конфигу вернул:

```
HTTP 400
CONFIGURATION_NOT_FOUND
```

Пользователь Firebase **не создавался**, снимки данных **не отправлялись**. Поэтому сквозное сохранение в реальном проекте пока не подтверждено. Клиентский конфиг не даёт прав включать провайдеры авторизации или публиковать серверные правила за владельца проекта.

## Что включить в консоли

1. Откройте нужный проект Firebase → **Authentication → Get started / Начать**.
2. **Sign-in method / Способы входа → Anonymous / Анонимный → Enable / Включить → Save**.
3. Откройте **Realtime Database → Rules / Правила**.
4. Замените правила содержимым `database.rules.json` из этой папки и нажмите **Publish / Опубликовать**.
5. Убедитесь, что URL именно нужной RTDB соответствует вашему конфигу. APK не пытается угадывать регион или создавать новую базу.
6. В приложении: **Витрина → Все сервисы → Сохранение данных**. Включите сохранение и нажмите **Сохранить сейчас**.

Нормальный конечный статус — **«Все изменения сохранены»**. Он показывается только после успешной записи RTDB, не просто после локального сохранения.

**Не выставляйте `.read: true` и `.write: true`.** В приложении есть проверка: сначала записывается безличный временный nonce, затем проверяется, что ни nonce, ни путь снимка нельзя читать без авторизации. Если доступ открыт, профиль/счета/история не загружаются и показывается ошибка правил. Nonce удаляется.

## Структура базы

```
users
  <Firebase Auth uid>
    snapshot
      schema: 1
      package: com.mvt.tbank
      clientNumber: постоянный 12-значный номер профиля
      writer: идентификатор установки
      revision: версия локальных изменений
      updatedAt: серверное время
      stateJson: весь сохранённый JSON состояния
      sha256: контрольная сумма stateJson
      accountCount: количество счетов
      avatar: выбранное фото, если есть
```

`stateJson` намеренно хранится строкой: RTDB удаляет пустые массивы/объекты и `null` в обычном JSON-дереве. Каноническая строка сохраняет их и восстанавливает исходные типы без потерь. Это не шифрование содержимого базы; защиту чтения обеспечивает Firebase Auth + закрытые правила вашего проекта. Владелец проекта по-прежнему имеет административный доступ через консоль.

Сохраняются профиль, счета, остатки, история, настройки, избранное, карты лояльности/дополнительные карты, заявки, резюме, подарки, подписки, портфель и выбранный аватар. Формы, которые ещё не отправлены/не сохранены, не считаются подтверждёнными данными.

## Что не отправляется

- Код-пароль приложения, его соль/верификатор и служебные токены авторизации.
- Временный экран блокировки и ожидающий локальный переход к результату.
- Кадры камеры, частные исходные записи/скриншоты из задания, приватный ключ подписи.

Код-пароль проверяется локально с PBKDF2-HMAC-SHA256 и случайной солью; после нескольких ошибок действует задержка. Firebase refresh token защищается Android Keystore / AES-GCM, без резервного хранения открытым текстом.

## Офлайн и восстановление

- Каждое финансовое действие сначала надёжно сохраняется на устройстве, не ждёт сеть.
- Изменения объединяются и отправляются последним актуальным снимком; ошибки соединения не обнуляют локальные данные.
- Чтение с ETag и условная запись `If-Match` защищают от незаметного затирания новой версии.
- При запуске более новая корректная копия того же Firebase-профиля может быть восстановлена, если локальная версия не изменилась за время запроса.
- Анонимный профиль привязан к этой установке: очистка данных/переустановка удаляет её локальные Firebase-ключи. Один цифровой номер не является способом авторизации и не открывает чужие данные.
- Для переноса на другой телефон используйте экспорт/импорт JSON. Экспорт не содержит PIN и Firebase-ключей. Для полноценного входа в тот же облачный аккаунт с разных устройств понадобится отдельное привязывание постоянного Firebase-способа входа.

## Дополнительные ограничения проекта

Если API key ограничен Android-приложениями, разрешите пакет `com.mvt.tbank` и сертификат этой сборки. Если включён обязательный App Check, необходима отдельная настройка поддерживаемого провайдера; клиент не обходит эти проверки и не отключает TLS-проверку сертификатов.

Реального банковского сервиса, SMS/НФС-эквайринга, торговой биржи или получения данных из настоящего банка нет. Предупреждение о вымышленных данных показывается один раз на установку, до включения сохранения.
